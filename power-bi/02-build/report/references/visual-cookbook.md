## Theme vs per-visual — what goes where

The report **theme** should handle defaults automatically: table/matrix row banding + header styling + grow-to-fit; bar/column data labels on, value axis + gridlines hidden, borders off; card bold values + labels + tight spacing; line smooth curves + shaded area + sparse labels; slicer header/item fonts; global hidden visual headers + drop shadows.

Some treatments are design intent but need **per-visual** implementation. Record them in the brief; `../format/` owns the PBIR JSON mechanics.

| Design requirement | Affects | Why per-visual |
|---|---|---|
| Rounded container corners | Containers | Card-like layouts / softer tones |
| Explicit card/container background | Layering | When page vs visual surfaces differ |
| Padding / internal spacing | Containers, cards | When whitespace is part of the identity |
| Chart/table title + subtitle state | Charts, tables | Deliberate titles without noisy autogenerated subtitles |
| Card accent bars / outlines | KPI cards | Card identity is per-metric |
| KPI value color + label text | KPI cards | Content-specific |
| Bar sort order | Bar/column | Sorting carries analytical meaning |
| Data-color gradients / highlighted categories | Bars, matrices, heatmaps | Colors depend on the specific measure/category |
| Page background opacity | Canvas | Tinted or dark surfaces |

## Visual-type sanity checks

Pick the type from the analytical question first — full framework in [chart-selection.md](chart-selection.md); confirm the PBIR `visualType` name in [`../add-visual/_index.md`](../add-visual/_index.md). Use this table only as a quick pre-config sanity check.

| Situation | Prefer | Avoid / switch when |
|---|---|---|
| Single KPI | `cardVisual` | Don't chart one number unless trend/context is needed |
| Ranked categories | `barChart` horizontal | >15 categories → TopN/Other or `tableEx` |
| Long category labels | `barChart` horizontal | Avoid vertical columns with rotated labels |
| Few time periods (≤6) | `columnChart` or cards | Avoid line with 1–2 points |
| Continuous trend (≥7 points) | `lineChart` | Avoid text month/quarter axes |
| Part-to-whole ≤5 slices | `donutChart` (only if share is the question) | Sorted bar if comparison/ranking is the point |
| Part-to-whole >5 slices | sorted `barChart`, `treemap`, 100% stacked | Avoid donut/pie |
| 2–3 same-unit measures | clustered bar/column or multi-line | Don't mix unlike units |
| 4+ series | small multiples or TopN + Other | Avoid spaghetti lines / overcrowded clusters |
| Exact lookup/detail | `tableEx` / `pivotTable` | Avoid chart when precision is the task |
| Correlation/clusters | `scatterChart` | Avoid dual-axis line/bar combos |
| Variance/deviation | waterfall or diverging bar | Avoid arbitrary color without a baseline |
| Geography matters | `azureMap` | Sorted `barChart` when geography is only a ranking; avoid legacy `map`/`filledMap` |
| Operational status | cards + table + status icons/CF | Avoid decorative gauges |

## Bar & Column (`barChart`, `clusteredBarChart`, `columnChart`, `clusteredColumnChart`)

Comparison across categories (bar = horizontal, column = vertical). Horizontal is the **default** — handles long labels and >7 categories. **Minimum ~6 categories**; with ≤5 use a donut or stacked bar.

- **Sort by value descending** via `sortDefinition` unless the axis has natural order (Date/numeric — NOT text month/quarter names, which sort alphabetically).
- **Data labels on** (`labels.show: true`, `OutsideEnd`); then **hide the value axis** + gridlines (redundant).
- **Value-gradient coloring**: single-measure bars are one color by default — apply a `dataPoint.fill` `linearGradient2` FillRule (darkest = highest) with `dataViewWildcard { matchingOption: 0 }`. ⚠️ Gradient stops **must** use `Literal` hex — `ThemeDataColor` renders black inside FillRule. Works best when max/min ≤10×; extreme skew → TopN or pull the outlier to a card. Each chart on a page gets a different hue; never reuse a hue already used by a card on that page.
- Clustered (AC vs PY): contrasting colors (amber + teal, not two blues).
- Category axis 10pt muted grey (`#605E5C`), no title, `innerPadding: 30`. `valueAxis.start: 0` — never truncate the baseline. Hide bar borders. Hide legend when the axis already names categories.
- Color rule: same measure as a card → match the card color; breakdown of a measure → gradient of that color; different measure → different hue ([color-palettes.md](color-palettes.md)).

## Line & Area (`lineChart`, `areaChart`)

Trend over continuous time — only if ≥3 time points (else cards/column).

- **Smooth**: `lineChartType: "smooth"`, `interpolationSmooth: "monotoneX"`.
- **Shaded area**: `areaShow: true`, `areaMatchStrokeColor: true`, area transparency 80–85%.
- Line width 2–3px hero / 1px context. Color via `dataPoint.defaultColor` — match the card for the same measure.
- **Markers**: hide at ≥12 points; show `circle` 4–5px below 12.
- **Data labels** sparse, neutral dark `#252423` (never accent), `labelDensity: 25`, position `Above`.
- Multi-line: 3–4 series max; beyond that small multiples, or highlight one + grey the rest.
- **Reference line** for average/target: dashed grey `#A19F9D`, width 1.5, `dataLabelText: "ValueAndName"`.
- Date axis: never text month/quarter names as Category (alphabetical) — use a Date or Month-Number column.

## Card (`cardVisual`)

Single headline metric. Use `cardVisual` (`card` is deprecated).

- Show enough context to avoid bare-number ambiguity — `referenceLabel`/subtitle ("+12% vs Q2 ▲", "across 3 subjects").
- Distinct accent color per card; left `accentBar` in that color. No internal border (`outline.show: false` — per-visual, not theme). Human-readable `label.text`.
- Height ~11–15% of page (≈96px on 1280×720, 120px on 1920×1080). Read `page.json` w/h then compute.
- **Never a bare one-measure card as the page hero/largest visual** — a prominent card must be a composite KPI treatment (value + delta/reference + sparkline/threshold + nearby "why it matters"). Otherwise move it to a KPI strip and give the hero to a trend / ranked-driver / variance / map / table / decomposition.
- ⚠️ `outline`, `accentBar`, `layout`, `padding` use instance selectors (`id: "default"`) and do **not** cascade from theme `visualStyles` — set per-visual. If you set any VCO property per-visual, also set `padding` per-visual or PBI resets it to ~5px.

(Deeper card recipes: [cards-and-kpis.md](cards-and-kpis.md).)

## Table (`tableEx`)

Detail lookup — reading specific values, not detecting patterns. Use `tableEx` (not legacy `table`).

- **Grow-to-fit**: `columnHeaders.autoSizeColumnWidth: true`, `columnAdjustment: "growToFit"`.
- Headers bold, `#F3F2F1`, 10–11pt. Values 10pt, right-align numeric, left-align text.
- **Alternating rows** via `backColorPrimary` (`#FFFFFF`) + `backColorSecondary` (`#FAFAFA`) — subtle. **Must** also set `fontColorPrimary`/`fontColorSecondary` or text goes invisible.
- Sort by the most interesting column descending. **Data bars** CF on the primary numeric column; **icon set** CF on a status/result column.
- >20 underlying rows → Top-N filter. Total row for additive measures only.

(Deeper table/matrix recipes: [tables-and-matrices.md](tables-and-matrices.md).)

## Matrix (`pivotTable`)

Cross-tab with row + column grouping (not legacy `matrix`).

- Same grow-to-fit + alternating rows. Row headers bold left; column headers bold centered.
- Subtotals for the dimension the audience cares about. Stepped layout for hierarchies.
- **Color-gradient CF** (`fillRule`) on value cells for the heatmap pattern. Set `expansionStates` for the default expand/collapse.

## Slicers

2–3 per page max — pick the dimensions that control the most visuals. Don't slice by a field already on a chart's category axis.

| Data | Type | `visualType` |
|---|---|---|
| Categorical ≤10 | Button/tile | `advancedSlicerVisual` |
| Categorical 10–50 | List | `listSlicer` |
| Categorical >50 | Dropdown | `slicer` (Dropdown) |
| Period selector | Dropdown/tile | `slicer` (Dropdown) / `advancedSlicerVisual` |
| True date range | Date picker | `slicer` (Between) |

**Temporal slicer** — choose from the page question + grain, not just the presence of a date column: executive/annual ≤10y → Year dropdown/tile; discrete-period compare (2020 vs 2023) → multi-select dropdown (`Between` = continuous, not discrete); 12–36 periods → period dropdown/relative date; arbitrary day/month exploration → full-date `Between`; integer/text date key or non-rendering picker → dropdown on Year/Period.

**Placement**: 1–3 slicers → inline with the title row (right side), full chart width preserved; 4+ → vertical filter rail 200–240px left. Never a rail for ≤3 (wastes column height); never top-left (that's the page title). Fill vs Light variants share border radius 8, `#E8E8E8`.

## Textbox (titles, annotations)

- Page title (H1): 20pt SemiBold, `#252423`, top-left, width ≥600px.
- Section dividers → use `shape` (rectangle), not textbox (textbox has ~24px min height).
- Dynamic text: bind to a measure for data-driven titles.
- ⚠️ **Avoid the scrollbar**: `h_min = max(18, ⌈fontSize_pt × 25/16⌉) + pad_top + pad_bottom` (10pt→34px, 20pt→48px with 8+8 padding). VCO border adds 0px. `paragraphs` is a native JSON array — never stringify it.

## Shape (`shape`)

Dividers, section backgrounds, annotation arrows, call-out boxes. Divider: rectangle h=2, full width, `#E0E0E0`. Section background: rounded rect low-opacity `#F5F5F5`, z-ordered behind the visuals it groups. `fill`/`outline`/`text`/`shadow`/`glow` **must** carry `"selector": { "id": "default" }`; the `shape` geometry object needs no selector.

## Scatter (`scatterChart`)

Relationship between two continuous variables. Label both axes with measure + unit. Bubble size sparingly (area encodes poorly). Data labels on outliers only. Quadrant `referenceLine`s (H + V). Color by category for identity, not magnitude. Play axis for time-lapse if a date dim exists.

## Waterfall (`waterfallChart`)

Sequential additive contribution / variance bridges. Sentiment colors: increase `#1AAB40`, decrease `#D64554`; total a distinct neutral (`#0072B2`/grey). Data labels always on; name each step; show connector lines. (Full recipe: [`../../recipes/waterfall/`](../../recipes/waterfall/).)

## Treemap (`treemap`)

Part-to-whole with >10 categories (not comparison — use bar). 1 grouping level unless the hierarchy is the point. Categorical palette so each rectangle is distinct; label name + value/% inside; size encodes magnitude.

## Conditional formatting (use when it reinforces the page's main pattern)

| Technique | Use on | Effect |
|---|---|---|
| Per-series color | Bar/column | Distinct color when category identity matters |
| Threshold color | KPI cards | Background/font by good/neutral/bad thresholds |
| Data bars | Table numeric columns | In-cell magnitude at a glance |
| Icon sets | Table status columns | Pass/fail / traffic-light scannable |
| Color gradient | Matrix cells, heatmaps | Min→mid→max reveals patterns |
| Highlight + grey | Any chart | One series accent, rest `#BDBDBD` — draws the eye |

**"All bars same color" problem**: single-series bar charts render every bar the same by default — specify per-category colors or a sequential gradient in the brief; `../format/` handles the mechanics.
