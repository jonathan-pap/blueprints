# Spectrum Light

> Futuristic **telecom**: fibre and radio spectrum. Generated by
> [`../../telecom-churn/build_theme.py`](../../telecom-churn/build_theme.py), which audits the
> palette and **fails the build** on any miss.

Light rather than dark, because the intended audience is Power BI Service *plus* a printable
executive summary.

## Palette roles

| Role | Hex | Reads as |
|---|---|---|
| Stayed | `#0E7490` | fibre cyan-teal — a connected line |
| Churned | `#9D174D` | deep magenta — a dropped line |
| Joined | `#9575F5` | electric violet — a new signal |
| Baseline / neutral series | `#334166` | slate — context, not message |
| Ink | `#0B1020` | primary text |
| Ink 2 | `#4A5578` | secondary text, column headers |
| Ink 3 | `#6E7A9C` | axis labels, slicer headers |
| Canvas | `#F1F4FB` | page background, cool near-white |
| Surface | `#FFFFFF` | card background |
| Rule | `#DEE4F2` | gridlines, card borders |

Status mapping is three-way — `Churned` / `Stayed` / `Joined` — not a red/green pair, so it does not
lean on the one colour contrast that colour-blind readers lose.

## Three gates, all enforced at build time

1. **WCAG contrast** — 4.5:1 for text, 3:1 for graphical objects, against both surface and canvas.
2. **Greyscale separation** — ≥1.30:1 between every status pair, so the printed exec summary still
   distinguishes them.
3. **CVD separation** — deuteranopia and protanopia simulated with the Viénot 1999 LMS transform;
   every status pair must stay ≥0.18 apart.

Gate 3 exists because the obvious telecom palette (orange/blue) is *also* the most colour-blind-safe
pair there is — it is why Okabe-Ito uses vermillion. Swapping to magenta looked like it would cost
real accessibility, so it was measured rather than assumed:

```
vermillion palette   worst CVD pair distance  0.228
spectrum palette     worst CVD pair distance  0.219
```

A 4% give, not a loss. If you re-colour this theme, re-run the generator — it will refuse to write a
palette that looks fine to you and collapses for someone else.

## Notes

- Ships `$schema` (`reportThemeSchema-2.152`), the full `textClasses` set, wildcard defaults, and
  filter-pane styling (`outspacePane` + `filterCard`).
- Container chrome is suppressed for `textbox` / `image` / `shape` / `actionButton`. The wildcard
  `padding` that the theme checklist asks for **clips a textbox used as a heading** — it is zeroed
  for `textbox` and `image` specifically.
- `slicer` styles `header` and `items` with `textSize`, **not** `fontSize` — `fontSize` is silently
  ignored on both containers.
- Power BI Desktop re-registers a theme from its internal `name:`. Editing in place appears to do nothing; bump
  the version in the filename (and the `name:` inside) together.
